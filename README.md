# 開票研究

[開啟網站](https://taiwan-votetrace.papple23g.com/) · [開票統計](https://taiwan-votetrace.papple23g.com/statistics) · [問題回報與資料更正](https://github.com/papple23g/taiwan-election-counting/issues)

這個網站整理歷屆臺灣選舉的電視開票畫面，用圖表比較各來源的票數變化，並提供原始截圖和影片連結供查證。資料包括 2012、2016、2020、2024 年總統選舉，以及 2014、2018、2022 年六都縣市首長選舉。

## 怎麼看開票畫面

選擇年份、選區和電視台或資料來源，就能查看票數曲線及對應截圖。總統選舉固定顯示全國；選單只列出已收錄的資料。切換選區時，網站會盡量保留原來的來源；新選區沒有該來源時，會改用預設來源。電視外框的 ▲ / ▼ 按鈕可以依序切換來源，窄螢幕時按鈕位於畫面下方。

點選圖表上的資料點或原始票數表，就能查看對應截圖；截圖也可以點擊放大。選定有時間的資料後，票數圖會用垂直線標示「比較時間」。切換電視台或同屆選舉的選區時，網站會找時間最接近的主要畫面，並顯示兩者相差多久；時間差沒有上限，距離相同時選較早的畫面。連續轉台時會保留原本的比較時間；切換年份則重新設定。找不到有時間的主要截圖時，仍可手動查看原始票數和截圖。

票數圖預設顯示選舉當天 16:00–22:00。桌面版可用滑鼠框選放大；下方「走勢偏差」圖還可用右鍵框選縮小，按 Escape 取消。手機等觸控裝置可點選資料點與捲動頁面，也可使用瀏覽器的雙指縮放。時間範圍以外的資料和截圖仍會保留。

候選人曲線依參選政黨著色，無黨籍使用灰色；圖例依顯示時段內最後可讀的票數排序。曲線連接已知票數只是為了方便閱讀，並不表示中間缺少的票數已被補上。圖表上的方向鍵與 Home / End 可在主要觀測之間移動。

## 資料怎麼整理

網站將讀到的畫面分為「主要」、「補充」和「待確認」。曲線、偏差排名、持續領先統計和預設截圖使用主要觀測，並沿用其他既有排除條件。主要畫面即使無法確認計票單位，仍會收錄並標示票源未知；同一電視台的主要畫面若途中更換票源，仍歸在該台。可確認的插播、次要票板或同場同選區的並排雙票板列為補充；無法確認主次的畫面列為待確認。判定不單憑出現時間、票數大小、曲線平順程度或票板是否位於底欄。

補充及待確認的資料可在來源下方展開，查看票數、時間、計票來源、判定理由及截圖，但不納入曲線和統計。資料只有在同一畫面的候選人姓名與票數位數足以證實時才更正，並保留更正前後的數值和理由；讀不清的數字保持空缺。如果畫面本身出現票數減少或高於官方最終票數，仍保留畫面上的數字。**截圖讀值反映當時畫面，不等同官方確認的計票結果。**

圖表優先使用畫面時鐘或其他已核對的時間。有些影片可根據多次語音報時推估時間，頁面會標示「約」；這不是秒級校準，誤差可能超過 1 分鐘。若只能用 YouTube 直播起始時間加上影片位置估算，會標示「時間未核對」；因無法確認影片剪輯、存檔起點或延遲，誤差範圍未知。沒有時間依據的資料不畫入時間曲線，但票數和截圖仍可查看；不會用影片上傳時間代替開票時間。

各來源收錄的時段和可讀票數不同。缺少某位候選人票數時，不顯示該候選人的曲線；只有同一組候選人的票數完整時，才計算開票進度、當選人得票率與走勢偏差。沒有可定位時間的來源會顯示原因和原始票數表，完整票組仍可用來查看進度圖。缺資料不代表零票。

## 開票統計

「開票統計」整理各來源的開票走勢偏差，以及最終當選人開始持續領先時的觀測時間、票數和開票比例。可依年份與選區篩選，查看偏差長條圖、時間分布，以及票數或比例的分布；點選分布圖的區間可展開相關紀錄和截圖。詳細資料、計算方法及限制收在頁面下方。篩選條件和「僅使用已核對時間」會保存在網址中，方便分享或重新載入；縮放和選取的圖表區間不會保留。

每筆統計代表一個來源在一場選舉的資料。網站從完整且非零的主要票數中，找出最後一次其他人領先或並列之後，最終當選人持續獨自領先的第一筆觀測。如果第一筆就已持續領先，只能知道開始領先的時間不晚於該筆，不能當作精確換手時間；缺讀或未錄影的期間也可能發生換手。

每個來源在每場選舉至少需要 10 筆完整票數，才納入領先門檻分布和走勢偏差統計；達標也不代表涵蓋整個開票時段。未納入統計的原始資料、曲線和截圖仍可查看。票數和比例只計算網站已收錄的同一組候選人，部分選區的總數不等於全部候選人的有效票總數。

分布圖顯示有效筆數，以及第 25、50、75、90 百分位數：例如第 50 百分位數是中位數；其他百分位數採最近順位法。比例可查看完整範圍，或放大 0% 以上、未滿 5% 的區間；百分位數仍以篩選後的全部有效紀錄計算。沒有可用時間的紀錄仍可納入票數統計，但不納入時間分布；未核對的估計時間會另外標示。

走勢偏差衡量開票過程中，當選人得票率與最終得票率的差距，並按開票進度加權平均；計算只連接同影片、同計票來源及同時計區段，不跨區段。總表先平均同一電視台在同一場選舉的來源，再讓各場選舉占相同權重。各台收錄場次和時段不同，表中列出有效場數及開票進度 10%–90% 的覆蓋率；中選會只作參考，不參與媒體排名。統計使用全部已收錄時段，不受票數圖 22:00 顯示終點限制。

## 回報問題

資料錯誤或操作問題可到 [GitHub Issues](https://github.com/papple23g/taiwan-election-counting/issues) 選擇「資料更正」或「網站問題」，提供相關資料和可公開查閱的佐證。回報內容會公開，請勿附上個人敏感資訊。

## 本機使用與維護

使用支援 `DecompressionStream` 的現代瀏覽器開啟 `index.html`，即可離線使用。兩個頁面共用 `assets/election-runtime.js` 的資料和圖表程式，瀏覽器會在載入時解壓資料。離線使用時請保留所有前端 JavaScript 和完整的 `assets/frames/` 截圖；觀看影片仍需要網路。

專案的檔案總大小和實際磁碟占用，在操作過程及交付時都不得超過 **1 GB（1,000,000,000 bytes）**；完整規則見 [專案容量鐵律](AGENTS.md)。下載、備份和建置暫存須放在專案外。

HTML 引用共用 JavaScript 時，`?v=` 使用該檔案 SHA-256 雜湊的前 12 碼。更新程式或內嵌資料後，須同步更新兩頁的版本，避免新版頁面搭配快取中的舊程式。

截圖維持原解析度，使用 WebP、AVIF 或原始格式。`frontend-assets.json` 記錄圖片格式、壓縮品質、尺寸，以及原圖與交付圖片的 SHA-256 雜湊；壓縮圖片須核對票數、候選人和時間，未通過則提高品質或保留原圖。品牌標誌的來源和雜湊記錄在 `assets/logos/sources.json`，來源 ID 對照在 `assets/broadcaster-logos.js`。素材來自品牌官網或官方頻道；民視標誌來自 Wikimedia Commons，商標和圖檔權利歸原權利人。

此資料夾是靜態前端，不含研究管線或測試環境。[GitHub](https://github.com/papple23g/taiwan-election-counting) 保存程式和圖片雜湊清單，但 `assets/frames/` 截圖不納入 Git，因此單靠倉庫無法重建完整網站；也不要強制將忽略的截圖加入 Git。

## 部署

正式網址是 [https://taiwan-votetrace.papple23g.com/](https://taiwan-votetrace.papple23g.com/)。網站使用 Cloudflare Pages Direct Upload，專案名稱為 `taiwan-election-counting`，正式分支為 `main`。自訂網域須在該 Pages 專案中加入並完成 DNS 設定。

發布時，先在專案外建立輸出目錄，放入 `index.html`、`statistics.html`、`404.html`、`robots.txt`、`sitemap.xml`、`frontend-assets.json` 和 `assets/`。專案保留全部 7,616 張截圖；發布包排除原始路徑屬於林佳龍總部的 22 張未使用影格，保留其餘 7,594 張。輸出包清單與數量須依實際內容更新，並用清單中的交付圖片 SHA-256 逐檔核對；完整影格及原清單留在專案內。

從專案外使用 Wrangler 將完整輸出目錄發布到 `main`；工具快取和暫存也須放在專案外。Git push 和 Direct Upload 是分開的步驟，推送程式碼不會自動更新網站。發布前後量測專案容量，發布後確認 HTTPS、首頁、統計頁及截圖都能正常讀取。
