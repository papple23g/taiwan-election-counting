# 開票研究

[開啟網站](https://papple23g.com/) · [開票統計](https://papple23g.com/statistics) · [問題回報與資料更正](https://github.com/papple23g/taiwan-election-counting/issues)

專案的檔案總大小與實際磁碟占用在操作過程及交付時均不得超過 **1 GB（1,000,000,000 bytes）**，完整規則見 [專案容量鐵律](AGENTS.md)。

使用支援 `DecompressionStream` 的現代瀏覽器開啟 `index.html` 即可離線使用。兩頁共用 `assets/election-runtime.js` 的無損 gzip 資料與圖表程式，載入時在瀏覽器解壓；離線使用時亦須保留此檔及其他前端 JavaScript。請完整保留 `assets/frames/`，截圖、放大檢視與選點同步均使用其中的圖片。影片連結需網路。

本頁提供 2012、2016、2020、2024 年總統選舉，以及 2014、2018、2022 年六都縣市首長選舉。可在矩陣點選縣市與資料來源的交叉格，未收錄的組合以「—」表示。

得票數趨勢圖的 X 軸固定使用實際時間，所有年份、縣市、來源及 PNG 匯出預設及重設視圖均顯示選舉當日 **16:00–22:00**，軸名為「觀測時間」；拖曳可在此範圍內以矩形框縮放，PNG 匯出使用完整時段。範圍外的觀測與截圖仍保留，不延長票數圖的時間軸。優先使用畫面時計及已核對的校時依據；仍無法核時、但已取得該影片YouTube直播起始欄位者，可用直播起點加原始影片位置估算，並於頁面、選點時間及PNG匯出標示「時間未核對」。此估算未確認存檔起點、剪輯或延遲，誤差範圍未知；原始時計欄位不以估算值補寫。其餘缺少時間依據的觀測不畫入上方曲線，票數與截圖仍保留。各來源涵蓋時段與可讀票組不同，無法辨識的欄位保留缺值，截圖讀值不等同官方真值。只有固定候選人組的票數完整時，才計算下方開票進度、當選人得票率與走勢誤差。

同片多次語音報時經交叉核對後，可在報時夾住的區段提供分鐘級時間估計；頁面及匯出以「約」和估時說明標示。這類時間不是畫面時計或秒級校準，實際誤差仍可能超過1分鐘；區段外若採直播起點換算，另標示「時間未核對」，不沿用語音校時的精度。

來源沒有可定位的時間資料時，頁面顯示缺口原因與可點選的原始票數表，並保留截圖與完整票組的進度圖，不呈現空白時間座標軸。缺少任何候選人的票數時，該線條不顯示並列明姓名；沒有完整票組者不計算該來源的走勢偏差。這些狀態不代表零票，也不以影片上傳時間代替實際時間。

來源矩陣每列為縣市、每欄為資料來源；總統選舉只有全國一列。來源欄以品牌 logo 搭配完整名稱呈現，欄頭固定；寬度不足時按來源順序分成多組矩陣向下排列，每組保留縣市列，不必左右捲動。交叉格以 ○／✓ 表示未選取與目前選取。首頁左側導覽及手機選單均提供「開票統計」入口。以「電視臺(計票單位)」標示已確認採用單一外部票源者；混用或尚未確認者不加註。候選人線條依該屆登記參選政黨著色，無黨籍使用灰色；圖例依目前來源在顯示時段內最後可讀票數由高至低排列。每位候選人的已知觀測直接連線，不以底色或虛線標註缺讀與跳段；連線只作視覺引導，不新增缺值或改寫票數。下方得票率圖的最終得票率以實線表示。走勢誤差仍只在相同影片、計票來源與時計區段內積分，不跨段計算。


`statistics.html` 以文章呈現電視臺開票走勢與最終結果的差異，以及第一名何時不再換人。主文提供偏差長條圖、時間分布與觀測門檻分布三張圖；第三圖可切換開票比例及全國、六都票數。票數圖保留線性刻度，採約 20 個等寬區間（通常 12–30 箱），並在下方以短線標示原始觀測；樣本或不同票數太少時另行提示。短線的垂直錯開只為顯示重疊，不改票數位置。閱讀範圍可依年份與選區篩選，內文同步重算；點選分箱可展開文末的紀錄與影格。完整偏差總表、算法與所有來源紀錄保留於收合區。

統計頁亦提供與曲線頁相同的左側導覽；選取年份會前往該屆曲線，「開票統計」標示目前頁面。窄版以導覽選單開啟抽屜，支援 Tab、Shift+Tab、Escape 與返回按鈕；文章內的閱讀範圍仍獨立篩選統計資料。

統計單位為「來源 × 場選舉」。在完整、非零票組中，找出最後一次其他人領先或並列後，最終當選人持續獨自領先的首筆觀測；首筆便持續領先者以首筆位置作上限。圖中「觀測門檻中位數」包含這類上限，不能視為真正換手時間的精確中位數，也不能證明缺讀或未錄影區間無換手。票數及比例只使用同一組已收錄候選人，部分選區並非全部候選人的有效票總數。缺少可採用時計的門檻仍可納入票數統計，但不納入時間分布；未核對的直播起點估時另行標示，可切換僅看已核對時間。

偏差總表沿用各場現有的進度加權平均絕對偏差，對同台同場的來源先平均，再對各場等權平均。各台收錄年份、場次與進度涵蓋不同，表內列出有效場數與 10%–90% 區間的覆蓋率；中選會作參考、不參與媒體排名。分析使用全部已收錄時段，不受上方票數曲線的 22:00 顯示終點限制。

截圖維持原解析度，使用 WebP、AVIF 或保留原始圖片格式；各圖片的格式、壓縮品質與尺寸記錄於 `frontend-assets.json`。壓縮版本須通過票數、候選人身分及時間依據比對；未通過時採用較高品質版本或保留原圖。清單另記錄原圖與交付圖片各自的 SHA-256，原圖 hash 作來源識別；其餘原始研究檔案未隨此前端包保留。

此資料夾為可直接使用的靜態前端，不含研究管線或測試環境。Git 保存前端程式與圖片雜湊清單；截圖保留在 `assets/frames/`，不納入版本控制。

## 回報與部署

程式與圖片雜湊清單保存在 [GitHub](https://github.com/papple23g/taiwan-election-counting)。資料錯誤與操作問題請到 [GitHub Issues](https://github.com/papple23g/taiwan-election-counting/issues) 提供年份、選區、資料來源、問題與可公開查閱的佐證。回報會公開，請勿附上個人敏感資訊。

正式站台使用 Cloudflare Pages Direct Upload。Git checkout 不包含截圖，不能單憑 GitHub 倉庫重建完整網站；發布時須另備本機的完整 `assets/frames/`，以 `frontend-assets.json` 核對圖片。不要將忽略的截圖強制加入 Git。

先在專案外建立輸出目錄，放入 `index.html`、`statistics.html`、`404.html`、`robots.txt`、`sitemap.xml` 與完整 `assets/`，再從專案外使用 Wrangler 發布至 `taiwan-election-counting` 專案的 `main` 分支。輸出目錄、工具快取及暫存均須留在專案外；發布前後均應依容量鐵律量測整個專案。Pages 的 Git push 與 Direct Upload 為兩個獨立步驟，推送原始碼不會自動更新站台。

品牌 logo 使用本機原始圖檔，不依賴外站載入。來源 ID 對照保存在 `assets/broadcaster-logos.js`，圖檔、來源網址及 SHA-256 保存在 `assets/logos/sources.json`。素材取自各品牌官網或官方頻道，民視取自 Wikimedia Commons 的標誌檔案；品牌商標與圖檔權利歸原權利人。Logo 僅用於識別播出來源，與括號中的計票單位分開處理。
